# Передача Atlas следующему исполнителю

Прочитай `references/01_TECHNICAL_SPEC.md`, `ATLAS_DESIGN_LANGUAGE.md`, токены, компонентный контракт и copy. Открой `atlas-ui-kit.html` как референс, затем изучи desktop/mobile screenshots. Не заменяй компоненты растянутыми изображениями.

Цель — реализовать дизайн-язык Atlas в production-приложении. Сохрани тёплую светлую основу, синий действия, serif только в редакционных вводных и sans в рабочих данных. Используй semantic tokens вместо локальных цветов.

Неподвижные правила:
1. Условия найма, релевантность, свежесть и личный статус — разные оси.
2. Unknown не равно false; критичные неизвестные видны до раскрытия.
3. Никаких процентов вероятности оффера и неподтверждённых гарантий.
4. Source attribution и путь отклика определяются лицензией.
5. Страна/часы подтверждаются пользователем, не выводятся из CV.
6. Переход к отклику не означает отправку; auto-apply отсутствует.
7. Mobile не сжатая desktop-копия; sticky не перекрывает фокус.
8. Privacy-copy соответствует реализации; реальные CV не отправляются демо-коду.

Работай слоями: foundations → primitive components → domain components → results/detail → profile/saved → failure states. Определи типизированные contracts и stories. Для каждого изменения запусти доступные проверки и запиши реальные результаты в IMPLEMENTATION_STATUS.md. Различай specified, implemented и tested.

Не выдавай текущий HTML-прототип за backend, production UI-библиотеку, завершённый accessibility-аудит или проверенное исследование рынка. Реальные данные и API подключай только через одобренные source policies. Не покупай сервисы и не разворачивай production без разрешения.

Критерии первой приёмки: 320–1920 px без потери функций; keyboard modal/tabs/forms; нужные состояния из спецификации; объяснение основано на evidence; у каждого источника правильная атрибуция; основные переходы и возврат сохраняют пользовательский контекст.
