# S2-001 — ручной профиль, объяснимый подбор, сохранение

**Результат:** вошедший пользователь создаёт подтверждаемый ручной профиль,
видит детерминированный объяснимый подбор по снапшотам Himalayas (eligible /
needs_review / ineligible с reason codes) и сохраняет вакансии за собой.

**Не входит:** CV/upload (S3), письма, embeddings/LLM, скрытие с причинами,
пометка отклика, DST-точный 12-месячный расчёт (сезонный минимум двумя точками),
удаление аккаунта (только профили), второй источник.

**Контекст:** ТЗ 4.1/4.3, 9.2, 11, 13; схемы CandidateProfile/SearchProfile
(03_DOMAIN_CONTRACTS.schema.json); SP 2, 8 (ownership + негативные тесты двух
пользователей), 7 (Matching без генеративных токенов).

## Приёмка
1. Auth: next-auth@4.24.15 (JWT-сессия, httpOnly), регистрация с scrypt-хэшем;
   приватные операции только через серверную сессию; неавторизованный → 401.
2. Профиль: страна (ISO-2|null), IANA-таймзона, окна доступности, целевые роли,
   формы сотрудничества, zero_mandatory_attendance, минимум зарплаты (валюта/
   период/strict), show_needs_review; сохранение = новая версия (история
   версий сохраняется); удаление удаляет все версии профилей пользователя.
3. Подбор: детерминированные правила v1 (geography, employment, attendance,
   salary, overlap) с исходами pass/fail/unknown/not_applicable, reason codes
   из базового набора ТЗ 13.2; агрегация AND-в-опции / OR-между-опциями;
   гейты remote/lifecycle/policy → not_evaluated не показывается.
4. Объяснение: для каждой карточки — список правил с исходом, кодами причин и
   пояснением; needs_review в отдельной видимой вкладке; ineligible скрыт.
5. Сохранение: save/unsave/list только для владельца; пользователь B не видит
   и не меняет сохранённое A (негативный интеграционный тест).
6. unknown не превращается ни в fail, ни в pass; несопоставимая зарплата —
   SALARY_INCOMPARABLE, а не сравнение через выдуманный курс.
7. Fixture-бэкенд: /matched честно пуст (нет данных источника), без моков.

**Риск:** высокий (auth, персональные данные). Отдельный review владельца до
принятия; профили не уходят ни в какой внешний сервис.

## Откат
Удалить миграцию нельзя вслепую: `DROP TABLE saved_jobs, search_profiles,
candidate_profiles, users CASCADE` только по решению владельца; UI-страницы
возвращаются к заглушкам revert-ом коммита.
