# S4-002 — валидатор писем, needs_input, панель оснований

**Результат:** AI-генерация письма проходит детерминированную проверку
(запрещённые фразы, выдуманные проценты/годы, длина) и либо допускается
как `generated_checked`, либо возвращает `needs_input` с конкретными
вопросами. Пользователь видит панель «На чём основано» рядом с письмом.

**Не входит:** repair loop (один ограниченный повтор), general mode
(письмо без вакансии), семантическая проверка утверждений против
evidence (нужна отдельная модель/разметка), CL4 accessibility audit.

**Контекст:** CL 1.0 §7–12; AI-001/002 (шлюз уже на месте); S4-001.

## Приёмка
1. Валидатор (`src/server/letters/validator.ts`): детерминированные
   проверки без LLM — запрещённые фразы (§7), проценты не из входа,
   годы опыта не из профиля, длина 80–350 слов, отсутствие ключевых
   элементов (приветствие, роль, завершение).
2. Интеграция: маршрут генерации после AI-вызова прогоняет валидатор;
   провал → ревизия с origin=`needs_input` и списком вопросов; успех →
   origin=`generated_checked`.
3. Панель «На чём основано»: на странице письма показываются поля
   профиля (roles, country) и вакансии (title, company, geography),
   использованные в промпте.
4. UI: если origin=`needs_input`, редактор показывает вопросы и кнопку
   «Заполнить профиль» вместо пустого текста.
5. Тесты: unit — валидатор по всем типам провалов; integration —
   генерация с mock-транспортом, возвращающим текст с forbidden phrase →
   needs_input; e2e без изменений (AI невидим на fixture-бэкенде).

**Риск:** обычный. **Откат:** валидатор можно отключить флагом.
