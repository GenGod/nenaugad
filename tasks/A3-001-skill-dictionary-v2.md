# A3-001 — справочник навыков v2: точность извлечения и русскоязычные алиасы

**Результат:** извлечение навыков перестало «видеть» навыки в обычных словах и
начало узнавать русскоязычные названия; появился worklist словаря для
человеческой ревизии. Метрики подбора выросли: NDCG@5 0.903879 → **0.909773**,
NDCG@10 0.924056 → **0.942889** (агрегат по 6 профилям, golden-набор v2).

**Не входит:** импорт ESCO (решение владельца, см. ниже), морфология русского
языка (падежи), эмбеддинги/синонимия за пределами словаря (B1+).

**Контекст:** [бриф](../docs/design/2026-09-27-matching-implementation-brief.md)
(пункт A3); [исследование](../docs/research/2026-09-26-job-matching-research.md)
ч.1 метод 1 (нормализация навыков), ч.2 A3; находки A1-001 (ложные срабатывания
экстрактора) и A2-001 (потребление алиасов).

## Что изменено в `src/domain/skills.ts` (v1 → v2)

1. **Правило регистра для неоднозначных алиасов.** `AMBIGUOUS_ALIASES` (go, docs,
   bi, ml, ts, js, py, pg, rest, rust, spring, rails, swift, phoenix, canvas,
   queries, statistics) матчатся только в капитализированной форме: «We go
   fast» больше не даёт Go, «REST API» продолжает давать REST API.
2. **Исправлен дефект потребления алиасов** (найден при атрибуции этого же
   изменения): раньше потреблялось только первое вхождение алиаса, поэтому
   второе «Node.js» в тексте утекало в ложный матч `js → JavaScript`. Теперь
   потребляются все вхождения. Это и был источник прироста: в golden-наборе
   j05 получал фантомный JavaScript и обгонял j06 с более высокой оценкой.
3. **Дельта алиасов v2** (`ALIAS_DELTA_V2_ENTRIES`, 19 канонимов): русские
   названия (машинное обучение, глубокое обучение, нейронные сети, аналитика,
   кибербезопасность, информационная безопасность, базы данных, микросервисы,
   мониторинг, инфраструктура как код, автотесты, автоматизация тестирования,
   ручное/нагрузочное тестирование, управление проектами/продуктом, руководство
   командой, инженерия данных, дизайн интерфейсов) + ECMAScript для JavaScript.
   Дельта — отдельная структура, а не правка 60 записей: дифф показывает, что
   именно добавила v2, и словарь растёт предсказуемо.
4. **`hasAlias`** — узкий хелпер для worklist (матчингом не используется).
5. `SKILLS_DICTIONARY_VERSION` = 2.

## Новое: worklist словаря (`src/domain/dictionary-coverage.ts`)

`dictionaryWorklist(texts)` возвращает частотно отсортированный список
неизвестных токенов и печатается в отчёте `npm run eval:matching`. Это **не
метрика качества** (посты — в основном проза, «доля покрытия» была бы числом, с
которым нечего делать), а рабочий список для человеческой ревизии: роль и
доменные существительные отфильтрованы, чтобы список был действенным. Ничего
не добавляется в словарь автоматически.

## V1: ESCO (проверка источника, 2026-09-29)

Портал ESCO (esco.ec.europa.eu/en/about-esco): издатель — DG Employment, Social
Affairs and Inclusion Еврокомиссии; данные «consulted and downloaded free of
charge»; версия **v1.2.1 (release v5.7.0, последнее обновление 10.12.2025)**.
**Чего проверить не удалось:** точное название лицензии и условия
перераспространения на странице «about» не указаны — отдельная страница условий
не прочитана. Поэтому: импорт ESCO **не начат**, решение за владельцем, и до
решения никаких ESCO-данных в проект не попадает (это внешний контент, к нему
применимы правила источников).

## Ограничения

1. Падежные формы русского не поддерживаются («базами данных» не матчится) —
   точное совпадение алиасов; морфология выходит за объём v2.
2. Список `AMBIGUOUS_ALIASES` курируется вручную; расширять по мере находок
   (worklist и golden-набор это показывают).
3. Worklist — эвристика: часть токенов («native», «layer») приходит из составных
   терминов; решения принимает человек.
4. ESCO не подключён (см. V1).

## Риск и откат

вернуть `SKILLS_DICTIONARY_VERSION = 1`-семантику через `git revert` коммита A3;
ветка не слита.
