# S1-005 — HEAD-проверки закрытия Jobicy

**Результат:** воркер периодически проверяет канонические листинги Jobicy
методом HEAD: 404/410 в двух последовательных проверках → lifecycle `closed`
(с провенансом); любые другие исходы (429/5xx/сеть/редирект) никогда не
закрывают запись. Закрытые записи исчезают из каталога/подбора, но остаются
в «Сохранённом» с пометкой.

**Не входит:** HEAD-проверки Himalayas (у него полный фид со своей
lifecycle-политикой), удаление закрытых записей (retention разбирается),
уведомления.

**Контекст:** ТЗ 5.2 (Jobicy: HEAD карточки, 404/410 — сигнал неактивности,
другие ошибки не означают закрытие; «checking availability once or twice per
hour is generally sufficient»), 14.3 (закрытие только по явному сигналу;
ошибки API ≠ closed), 17 (breaking change не должен массово закрывать);
живой smoke URL-схемы листингов 2026-09-25.

## Приёмка
1. `headJobicyListing` в allowlisted fetcher: pinned jobicy.com, HEAD,
   `redirect:"error"`, таймаут; 200→active, 404/410→inactive, прочее→unknown.
2. Бюджет: ≤25 HEAD/час (rolling, персистентно в БД — рестарт не сбрасывает);
   per-record интервал ≥6 ч; не проверяются записи, недавно виденные в окне.
3. Закрытие: 2 подряд inactive (интервалом ≥6ч) → `lifecycle='closed'`
   (jsonb_set, провенанс и даты не переписываются); active сбрасывает счётчик;
   unknown не меняет.
4. Mass-closure guard: если в прогоне >50% inactive (при ≥4 проверках) —
   закрытия НЕ применяются, журнал получает `closure_quarantine`
   (подозрение breaking change), результаты проверок записываются.
5. Воркер выполняет проход проверки после импорт-цикла (для включённого
   jobicy); `--status` показывает статистику проверок; идемпотентность
   повторных проходов.
6. «Сохранённое»: закрытые записи видны с бейджем «Закрыта»; каталог/подбор
   исключают их автоматически (существующие гейты).
7. Тесты: unit (классификация, счётчики, guard), integration (SQL-поток на
   test DB с фейковым HEAD-транспортом: закрытие за 2 inactive, сброс active,
   unknown-нейтральность, бюджет, quarantine).

**Риск:** обычный (права не меняются — fetch уже allowed; HEAD листингов
покрывается «normal integrations» доков Jobicy). **Откат:** флаг воркера
`--no-closure`; записи reopen не делаем автоматически (только повторный
импорт окна вернёт active через versioning).
