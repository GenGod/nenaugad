# E6-002: Next.js 16.4.4 -> 16.4.5

**Status: implemented and tested locally 2026-11-04; committed, merged and pushed at the
owner's word once every check passed; not accepted.** Basis: [OPEN_GAPS](../docs/OPEN_GAPS.md) E.6, whose
note expected Next's scheduled security release on 2026-11-03 to list 16.4.4 (the version
[E6-001](E6-001-next-security-patch.md) installed). Next.js 16.4.5 was published to npm at
2026-11-03T18:01:54Z and is now `latest`.

## Result and boundaries

**User result:** none visible. The app runs on the 16.4 patch that fixes Next's November
2026 security advisories.

**Findings.**
- 2026-11-03, before the release notes were out: `npm audit` on 16.4.4 exit 0; the GitHub
  advisory database listed nothing against `next@16.4.4`; no GitHub release, tag or blog
  post for 16.4.5 yet.
- 2026-11-04 07:06 UTC: 16.4.5 is Next's November 2026 security release (GitHub release
  v16.4.5, 2026-11-03T18:38Z; blog "November 2026 Security Release": "v16.4.5 (Active LTS)
  and v15.5.29 (Maintenance LTS)"). It fixes seven advisories, published on Next's
  repository at 18:39 UTC:

| Advisory | CVE | What it needs |
|---|---|---|
| GHSA-mfr8-8qww-v76h | CVE-2026-119790 | Cache Components; a `use cache` function also called through `unstable_cache` |
| GHSA-vc7v-qv4w-wrv8 | CVE-2026-119351 | Cache Components; nested `use cache` functions reading a root param |
| GHSA-rhh4-g77r-r9qj | CVE-2026-119349 | `use cache` with security-significant binary arguments |
| GHSA-vvgp-ww4w-46vf | CVE-2026-119350 | self-hosted `next start`, Cache Components, a blocking fallback shell |
| GHSA-pc58-hwjq-p385 | CVE-2026-119348 | self-hosted; a route returns an attacker-controlled fetched `Response` unchanged, behind a pipelining HTTP/1.1 proxy |
| GHSA-f3mh-rxg3-f5g2 | CVE-2026-119346 | Edge route handlers setting cookies with `NextResponse.cookies.set()` |
| GHSA-7qx7-33qx-rqx2 | CVE-2026-119347 | image optimization of an allowed remote image, with an SVG-capable backend |

  All are medium on the repository; the blog calls GHSA-mfr8 high. The repository's
  affected ranges are uneven (several end at 16.4.2, others are open-ended, none names a
  patched version). None is in GitHub's reviewed advisory database yet (`gh api
  advisories/<id>`: 404), which `npm audit` and Next's agent upgrade check read, so
  `npm audit` still passes on 16.4.4. Once they are reviewed, 16.4.4 will likely be
  flagged, and dev and build would stop under an agent again. If a reviewed range stays
  open-ended, even 16.4.5 would be flagged until GitHub corrects it.
- **What 16.4.5 changes** (the 16.4.4 and 16.4.5 tarballs compared file by file): apart
  from the version string, only the files behind the seven fixes change: image type
  detection (`server/image-optimizer/detect-content-type.js`), response forwarding
  (`server/send-response.js`, `server/next-server.js`), the `use cache` wrapper and its
  work-unit storage, the app-page runtime, and the Edge adapter (`server/web/adapter.js`).
  The bundled docs are identical.
- **Exposure:** none of the seven reaches this app's code. Across the 18 route handlers in
  `src/`: no Edge runtime, no `NextResponse.cookies.set`, no `use cache`, `unstable_cache`
  or Cache Components, no `next/image` or `images` config, and no route returns a fetched
  `Response`. Nothing is publicly deployed.
- Dry run on copies of `package.json` and the lockfile: the lockfile moves only `next`,
  `@next/env` and the eight `@next/swc-*` binaries (the same ten entries as E6-001); nothing
  added or removed; `next`'s dependency, peer and engines ranges are unchanged apart from
  `@next/env`.

**Change.** `next` 16.4.4 -> 16.4.5, pinned exactly.

**Not changed:** application code (unless the bundled docs require it), other dependencies
(`@huggingface/transformers` stays exactly 4.3.0, `next-auth` 4.24.15, React 19.3.0), the
CI and weekly workflows, the coverage thresholds, `experimental.agentUpgrade: false` on the
e2e server (E6-001's decision).

**Risk: normal.** A framework patch touches every page and the auth stack, so the full set
of checks runs, `npm run build` and `npm run test:e2e` included.

**Data:** packages from the npm registry; the isolated test database. No provider call, no
spend.
